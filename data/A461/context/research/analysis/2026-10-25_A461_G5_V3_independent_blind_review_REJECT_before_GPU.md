But the canonical `Kev API render` serializes `received_messages` before a trailing `validator_set` field: appending a vote modifies the *middle* of the rendered state, so the old rendered state is **not** a text prefix of new rendered state. Independent reconstruction of V2 qualified donor `T2_WAIT_TO_REJECT:433890d19a90625e` from frozen G0 using pinned Kev `api.py` rendering found a first **character** mismatch at character 1686 of a 1735-character old state, with the old next text `validator_set:` but the new text being the newly appended vote. Source: `research/rounds/A461_G4_POINTER_READOUT_AND_BIDIRECTIONAL_PATCHING/G0ABC_REAL_20261025/g0c_anchor_map.jsonl` Git blob `7917352ae2d10287e0fdad24b1bc22a87ea913d9`. **P0-2: patch target is the WRONG independent question row (critical causal invalidity)** (runner **245–246, 159–165, 281, 290, 298, 354, 373, 394–409**). Pinned Kev `DecisionModel.forward_rows_batch` runs independent `state + question` rows because Qwen3.5 hybrid backbone cannot use packed block mask. Frozen G5 question order = `certificate_action` (batch row **0**), `conflicting_vote` (row **1**), `evidence_level` (row 2), `quorum` (row 3). Every `forward_patched` invocation supplies **`bi=0`**, and all capture slices `cap[(tag,L)][0,...]` / `cap_t[L][0,...]` use **action row 0**. Yet primary endpoint `c_read` extracts **conflicting_vote** row 1. Independent rows share the *parameters* but not inter-row activations, so changing action-row activations does **not** establish any intervention on the C readout; the C effect is expected to remain unchanged. Freeze row mapping from actual `rows_of`/meta, capture donor and host *on the same named question row*, patch `bi=C_idx`, and verify C changes under a positive synthetic hook-injection CPU test. Any independent off-target action/quorum experiment needs separately targeted row patches (and honest resource accounting); do not claim C→A serial mediation.
