## 补充观察（描述性）
1. **round span 不只是“无效”，而是把宿主推向“无冲突”。** 99/104 个单元 dM_round < 0，96/104 个低于剂量匹配随机。L11 的追加 span 携带的是供体对该票的**有符号评估**（冲突 / 不冲突），而不是一个“这里有一张投给其他块的票”的存在标记。
2. **供体自身读出正确。** kev-4B 在 14/14 个供体的 ROUND 前向中 M < 0，即模型在供体上下文里读到了轮次字段；没有供体把 ROUND 判为冲突，因此“已识别但无效”的混杂分层为空。
3. **轮次 token 在宿主坐标“看起来合法”时也不修复。** 10 个单元（4 组）中，ROUND 变体的轮次数恰好等于宿主的候选轮次：round 修复 0，main 修复 4。修复信息取决于**供体上下文中**的计算，而不是补丁位点处 token 与宿主角色的匹配（与 G1.0 Part III 一致）。
4. **换作者不削弱、反而略强。** okalt 66 vs main 53，72/104 个单元 dM_okalt > dM_main。修复不依赖具体作者 token，与“角色抽象的冲突评估”相容。okalt 更强的原因（作者标签、与支持票的距离等）未检验。

## 这说明什么、不说明什么
- **新增排除：** 在 L11 追加 span，修复不是由通用的“投给其他块的票”原型（H-CLS 的检验形式）驱动的。该状态对规则相关的轮次字段敏感，且对两个方向都有因果作用：合法冲突 → 修复，同形非冲突 → 压制。这是首次在同一 token 形式下分离“关系有效性”与“表面形式”，回答了 V2 审计 P0 与 G1.0 留下的 H-CLS 混杂。
- **对“宿主失败”的含义（候选）：** 失败宿主在 L11 的追加 span 里没有形成供体那样的正向冲突评估。这一结果支持 M1 的“关系评估在 span 位置的形成”是因果相关的环节，但**仍不能区分**以下两点：宿主是根本没算出（H-ENC），还是算出后被别处覆盖或未传到 span（M2 的路径问题）。
- **不说明：** 唯一编码失败机制、C→A 中介、读出路径、跨架构普适性；也不能说明全部四个 typed 输出都正确（本轮未评估 E/Q 的 Gold）。只有 kev-4B，一个层，一个模拟器家族。
